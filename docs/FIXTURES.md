# Real fixtures: storage, labelling and consent

Synthetic fixtures are generated by `:testing:fixtures` and need nothing from this page. **Real race footage** (F03b) is added under the same `labels.json` schema, but it is never committed.

## Storage decision

`surpdeh/belllap` is public, so real footage lives in a **private S3-compatible bucket** (Cloudflare R2 recommended; GCS via interop works too). Git LFS stays an option only once the repo is private. Recorded in [PLAN §1.7](PLAN.md).

Bucket layout:

```
golden/<fixture_name>/labels.json
golden/<fixture_name>/<fixture_name>.wav        # optional, if the clip has audio
golden/<fixture_name>/<fixture_name>_frames/frame_00000.png ...
```

## Fetching

```bash
export FIXTURES_S3_BUCKET=... FIXTURES_S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com
export AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...
scripts/fixtures/fetch.sh            # into testing/fixtures/real/ (gitignored)
./gradlew :testing:harness:replayReal
```

- Without credentials the script prints `SKIPPED` and exits 0.
- With no fixtures present, `replayReal` writes `build/reports/real-metrics.json` with `"status": "skipped"`. Treat that as **inconclusive**, never as a pass.
- The nightly workflow `nightly-real-metrics.yml` uses repository secrets `FIXTURES_S3_BUCKET`, `FIXTURES_S3_ENDPOINT`, `FIXTURES_S3_ACCESS_KEY_ID` and `FIXTURES_S3_SECRET_ACCESS_KEY`. A read-only bucket key is enough.
- Real-footage metrics are reported, not gating, until they are stable (see VERIFICATION.md threshold rule).

## Labelling guide

`labels.json` (schema in `Labels.kt`, version 1). All times are **PTS in nanoseconds** from the start of the clip, never wall clock.

| Field | Meaning |
|---|---|
| `bellOnsetsNs` | Sorted start of each bell strike sequence, on the audio time base |
| `flagIntervals` | `[startNs, endNs)` while the chequered flag is visibly waving; sorted, non-overlapping |
| `crossings` | One entry per rider's **front wheel reaching the finish line**: `frame`, `ptsNs`, and `group` (riders in a bunch share a number) |
| `distractors` | Sounds that must not trigger the bell (clapping, voice, freewheel) |
| `fps`, `framesDir`, `audioFile`, `sampleRate` | Where the media is and how to read it |

Steps:

1. Extract frames, e.g. `ffmpeg -i clip.mp4 -vf format=gray <name>_frames/frame_%05d.png` and audio `ffmpeg -i clip.mp4 -ar 16000 -ac 1 <name>.wav`.
2. Label by stepping frame by frame; label a crossing on the first frame the wheel touches the line.
3. Validate: `Labels.parse` rejects unsorted or overlapping labels, and `replayReal` fails fast on a malformed file.
4. Upload the directory to `golden/` (golden set, under about 2 GB) or another prefix for the larger set.

## Consent rules

- Only upload footage you filmed, or have written permission to use, from organisers and (for identifiable riders or minors) participants or guardians.
- Prefer footage framed side-on at the line; do not capture faces, plates or private property more than needed.
- Never commit footage, bell recordings, or bug-report media to git, issues or PRs. Field-report media is added to the bucket only with the reporter's consent.
- Keep a private note of who consented and when, next to the bucket, not in this repo. Remove a clip on request.
