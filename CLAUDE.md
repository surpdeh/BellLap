# BellLap: agent working rules

BellLap is an Android app (Kotlin, Compose, CameraX) that tracks the finishing order in cycling criteriums. It detects the bell lap by audio, waits for the chequered flag, records the finish and marks finish-line crossings for commissaire review.

- **Plan and backlog:** `docs/PLAN.md`. Each feature `Fxx` is a GitHub issue.
- **Architecture research:** `docs/research/technical-architecture.md`.
- **Verification:** `docs/VERIFICATION.md` and the `verify-belllap` skill.

## How to work an issue

1. Read the issue, `docs/PLAN.md` §2 (architecture) and the relevant section of the research doc. Restate the acceptance criteria and the required verification evidence.
2. Work on a branch named `feat/Fxx-short-name` (or `claude/...` when the harness assigns one). Use small commits with conventional-commit messages.
3. Write tests first for logic: state machine, detectors, sidecar and parsers.
4. Before opening the PR, run the tier 1 verification in `verify-belllap` and paste its output into the PR template's **Verification** section. **Report a check that could not run as inconclusive.**
5. Open the PR with `Closes #<issue>`. Then wait for CI, read the tier 2 evidence comment and fix any failures.
6. For risky or larger features, `/poteto-mode` (pstack) is available. Use `/architect` before writing code and `/interrogate` before review.

## Architecture rules

- Detectors (`:audio:*`, `:vision:*`) and `:core:statemachine` are **pure Kotlin/JVM**, with no `android.*` imports. They take plain arrays or the `Frame`/`PcmChunk` types, so they run in JVM tests and in Replay.
- All hardware goes through the `AudioSource`, `FrameSource`, `Clock` and `BeepSink` interfaces, and each has a file-backed or fake implementation.
- The time base is the **frame PTS**, never the wall clock.
- The foreground service must be started from a visible activity, never from the background (Android 14+ rule).
- Set minSdk 29 and targetSdk 36. Gate API 30+ features with `Build.VERSION.SDK_INT` checks.
- Use Apache, MIT or BSD licensed dependencies only. **No AGPL**, which rules out Ultralytics YOLO.

## Data rules

- Never commit real race footage, bell recordings from users, or bug-report media. The repo may be public. Real fixtures live in the private bucket (F03b).
- Synthetic fixtures are generated by code in `:testing:fixtures`. Commit the generator, not large outputs.

## Environment

- The Android SDK is at `$ANDROID_HOME` (`/opt/android-sdk`), installed by the belllap cloud environment's setup script. JDK 21.
- There is no emulator in the cloud container because there is no KVM. Emulator tests run in GitHub Actions (`.github/workflows/ci.yml`).
